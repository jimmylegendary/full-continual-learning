결과 이전 선택과 이후 책임 추정

06 §2 · 식 E1–E3

E1 · 결과 이전에 schema를 고를 확률

PROPOSAL 06 §2 줄 13

하는 일. 결과 yt를 보기 전에 어느 schema k를 쓸지의 확률 q−를 정한다.

입력 → 출력. 입력은 현재 입력 xt, 문맥 ct, 이전 시각의 depth bank D<t이고, 출력은 schema별 선택 확률 qt,k−다.

qt,k−=qψ(k∣xt,ct,D<t)

기호. 위첨자 −는 "결과를 보기 전"을 뜻한다. qψ는 controller ψ가 내는 분포, 세로선은 조건부, D<t는 t 이전의 depth bank다(문서가 따로 정의하지 않아 §1의 Dt,r에서 읽었다).

E2 · schema별 예측을 섞은 예측분포

PROPOSAL 06 §2 줄 15

하는 일. schema별 예측을 q−로 가중 평균해 결과의 예측분포를 만든다.

입력 → 출력. 입력은 qt,k−와 각 schema의 느린 파라미터 θk, fast state ϕk,t, 입력 xt이고, 출력은 결과의 예측분포 p(yt∣xt,D<t)다.

p(yt∣xt,D<t)=∑kqt,k−pθk,ϕk,t(yt∣xt)

기호. ∑k는 모든 schema에 대한 합, pθk,ϕk,t(yt∣xt)는 schema k가 내는 예측이다.

E3 · 결과를 본 뒤의 책임 추정

PROPOSAL 06 §2 줄 19

하는 일. 결과 yt를 본 뒤 각 schema가 그 결과에 얼마나 책임이 있었는지를 q−와 우도(결과가 나올 확률)의 곱에 비례하게 다시 계산한다.

입력 → 출력. 입력은 qt,k−와 관측된 yt에 대한 schema k의 우도이고, 출력은 책임 γt,k(관측 후 attribution)다.

γt,k∝qt,k−pθk,ϕk,t(yt∣xt).

기호. ∝는 비례 기호다. 정규화 상수는 문서에 적혀 있지 않다.

PROPOSAL q−는 판단에, γ는 관측 후 attribution·update에 쓴다. 평가용 future label이나 latent cause를 learner·controller에 제공하지 않는다. 같은 우도가 성립하는 구조들은 현재 관측만으로 구별할 수 없을 수 있다(06 §2).

USER (U-T09) 주어진 schema에 따른 빠른, 편향된 추론을 원한다. PROPOSAL 편향은 오류를 고집하는 성향이 아니라 결과 이전의 조건부 prior qt,k−가 경험으로 한쪽에 집중된 정도다. 집중도는 H(qt−)=−∑kqt,k−logqt,k−(문서에서는 문장 안 식)로 둔다. 작을수록 편향이 강하다. 유용한 편향은 schema 일치 사례에서 H(q−)가 작고 정답률이 유지되며 필요한 계산이 줄어드는 경우다. 해로운 편향은 불일치 사례에서도 H(q−)가 작아 γt,k가 관측 쪽으로 옮겨 가지 못하는 경우다. 따라서 편향은 H(q−) 자체를 최소화하는 목표가 아니라 검증 체계의 편향 이득·해악 지표로 보고한다(아래 핵심 측정량 절). OPEN continuous routing이나 분산 mixture에서는 엔트로피 대신 유효 schema 수 같은 대체 척도를 정한다.

쉬운 설명 — 시험 보기 전의 예상과 채점 뒤의 책임

문제. 모델이 "이 문제는 A 유형이야"라고 먼저 믿고 풀다가 틀리면, 누구 탓인지 알아야 고칠 수 있다.

해결(제안). 풀기 전의 믿음(q−, 예상)과 정답을 본 뒤에 다시 매긴 책임(γ)을 따로 둔다. 예상이 한쪽으로 쏠려 있으면 빠르지만 고집이 될 수 있다. 정답을 보고도 책임이 옮겨 가지 않으면 그것이 해로운 편향이다.

왜 그냥 되지 않는가. 정답을 모르는 때 쓰는 값에 정답(미래 label)을 섞어 넣으면 "예상"이 아니게 된다. 그래서 q−는 결과 이전 정보로만 계산한다.

이 설명에서 생략한 것 — 책임을 합 1로 맞추는 정규화(문서에 쓰여 있지 않다), 이 확률을 실제로 어떻게 학습하는지, "유효 schema 수" 같은 대체 척도.

E4 · 빠른 업데이트의 손실

PROPOSAL 06 §3 줄 29 · Titans에서 영감을 얻은 후보

하는 일. 빠른 업데이트가 줄이려는 값을 기억 정확도·관측 예측·피드백 세 항의 가중합으로 쓴다.

입력 → 출력. 입력은 세 손실과 가중치이고, 출력은 하나의 손실 ℒtfast다. 문서는 이를 "기억 정확도·관측 예측·피드백을 구분한 예"라고 부른다.

ℒtfast=λkvℒkv+λpℒpred+λfℒfeedback.

기호. ℒkv는 기억 정확도 항(kv는 key–value로 읽힌다), ℒpred는 관측 예측 항, ℒfeedback은 피드백 항, λkv,λp,λf는 각 항의 가중치다.

E5 · fast state를 바꿀 누적량

PROPOSAL 06 §3 줄 31 · Titans에서 영감을 얻은 후보

하는 일. schema k의 fast state를 바꿀 방향을, 이전 누적량과 책임으로 가중한 기울기를 합쳐 갱신한다.

입력 → 출력. 입력은 이전 누적량 mk,t−1, 감쇠 βt, 학습률 ηt, 책임 γt,k, 기울기이고, 출력은 새 누적량 mk,t다.

mk,t=βtmk,t−1−ηtγt,k∇ϕkℒtfast

기호. ∇ϕk는 ϕk에 대한 기울기다. 식의 모양이 momentum 갱신과 같지만 문서는 m과 βt에 이름을 주지 않았다. 책임 γt,k가 곱해져 있어 책임이 큰 schema일수록 크게 움직인다.

E6 · fast state의 한 단계 갱신

PROPOSAL 06 §3 줄 33 · Titans에서 영감을 얻은 후보

하는 일. fast state를 일정 비율 잊고(decay) 새 누적량을 더해 한 단계 갱신한다.

입력 → 출력. 입력은 ϕk,t, 감쇠 αt, mk,t이고 출력은 ϕk,t+1이다.

ϕk,t+1=(1−αt)ϕk,t+mk,t.

기호. αt는 decay·retention 표기의 선택이다(문서). 1−αt는 남는 비율로 읽는다.

PROPOSAL 이 식들은 Titans에서 영감을 얻은 후보이지 모든 HOPE·Titans 구현(HOPE는 Nested Learning 논문의 구조 이름)의 동일 식이라는 뜻이 아니다. 입력별 계수의 범위·norm·root budget을 사전 명세한다. 작은 학습률이 안정성 전체를 보장하지 않는다(06 §3).

학습 방법은 optimizer 하나로 묻지 않는다

USER (B08, 2026-10-09) 학습은 적은 data로 빠른 일반화의 오류(overfitting)를 유도하고 시간축 continual learning으로 그 오류가 상황에 맞게 사라지게 하는 것이다. GD→SGD→Adam→Muon 같은 일반 optimizer가 맞는지 묻고, backward·SGD 수준의 근간 학습 방법을 조사·고찰하라고 했다. PROPOSAL 그래서 학습 방법 선택을 다섯 결정 축으로 분리해 기록한다. E4–E6은 그중 넷째 축의 후보 하나다.

  1. 학습 신호·목적: 실제로 새로 관측한 것이 무엇이며 다음 판단의 어떤 차이가 중요한가.
  2. 귀속: 어떤 관계·경로가 결과에 기여했는가.
  3. 바뀌는 상태: fast ϕ, slow θ, controller ψ, memory M 중 무엇인가.
  4. 갱신 규칙: 국소 규칙인가 gradient optimizer인가.
  5. 가소성·시간척도: 학습량·망각·보존·통합을 언제 조절하는가.

표준 optimizer(예: AdamW)는 느린 층의 기준선으로 같은 신호·예산의 대조군에 둔다. optimizer를 바꾼다고 적은 경험에서 유용한 문맥이 자동으로 발견된다고 가정하지 않는다(06 §3). ARCHIVE Melete도 모델 구조·기억의 상태와 시간척도·학습 목표·credit assignment와 update rule·optimizer를 서로 다른 축으로 두었고, 큰 data에서의 성공이 알고리즘의 대량 data 요구를 뜻하지는 않는다고 기록했다. OPEN B08의 "오류를 유도한다"를 "빠른 가설 생성의 부작용을 허용하고 시간축 반례로 줄인다"로 읽는 것은 Melete 문서의 해석이며 사용자 확인이 필요하다(design-audit §5 B군 11번).

사용자 확인 필요 — B08의 "오류를 유도한다." "적은 data로 빠른 일반화의 오류(overfitting)를 유도한다"를 "성급한 일반화를 허용하고 시간축 반례로 줄인다(오류를 높이는 목적함수는 아님)"로 읽어도 되는가. 이 읽기는 Melete 문서의 해석이며 확정 전까지 OPEN이다(design-audit §5 B군 11번).

문헌 정독이 남았다 — 근간 학습 규칙 후보 지도. fast-state 계열(TTT(test-time training)·Titans·DeltaNet), eligibility·three-factor 계열, 국소 신용 계열(predictive coding·Forward-Forward 등)의 원문 근거, library 존재, 수학적 정의의 완결 여부를 표로 만드는 일이 남았다. E4–E6은 그 지도 없이 쓴 후보 하나다(design-audit §6 6.2 항목 3, 11 §7).

E7 · 적응 뒤 새 사례 일반화 목적함수

PROPOSAL 06 §4 줄 57 · 새 schema 생성 비용·경쟁 규칙은 후보 가설

하는 일. 새 과제의 support로 m회 적응한 뒤 독립 query로 잰 손실의 기대값에 보존·등변성·용량 항을 더해, 느린 파라미터 θ와 controller ψ를 찾는다.

입력 → 출력. 입력은 과제 분포와 과제별 support Sτ·query Qτ, 적응 횟수 m이고, 출력은 최소화하는 θ,ψ다.

minθ,ψ𝔼τ[ℒQτ(Adaptm(θ,ψ;Sτ))]+λretℒretention+λeqℒequivariance+λcapC.

기호. 𝔼τ는 과제 τ에 대한 기대값, Adaptm(θ,ψ;Sτ)는 support로 m회 적응한 결과, ℒQτ는 query 손실이다. λretℒretention은 보존 항, λeqℒequivariance는 등변성 항, λcapC는 용량 항이다(문서는 이 C를 따로 정의하지 않았다).

PROPOSAL 단순 reconstruction이 아니라 이후의 전이·학습 효율이 objective에 들어간다. 이름·대상 순열 g가 출력에도 반영돼야 하는 과제에서는 f(gx)≈gf(x)의 equivariance(변환을 가해도 출력이 같은 방식으로 변하는 성질)를 사용한다. 모든 변환에 invariant(불변)하면 오히려 역할 차이를 잃을 수 있다. 새 schema 생성 비용·representation expansion·경쟁/통합 규칙은 후보 가설이고, rank나 모듈 수가 늘었다는 사실만으로 schema 분화를 선언하지 않는다(06 §4).

  • LITERATURE (fulltext-read) 느린 구조를 얻는 방식은 논문마다 다르다. MICONI25는 바깥 루프(A2C(advantage actor-critic)와 BPTT(backpropagation through time))와 gradient 없는 안쪽 Hebbian trace를, TEM20은 바깥 BPTT(25 step, 4-lap은 100)와 환경마다 0으로 리셋하는 안쪽 Hebbian M을 쓴다.
  • LITERATURE (fulltext-read) GOUDAR23과 CHU25에는 명시적 meta-objective가 없고, GOUDAR23의 문제 경계·Adam 리셋·안정화 정규화와 CHU25의 단계 경계는 실험 틀이 공급한다. GOUDAR23에서 재사용을 막으면 가중치 변화가 약 8–12배 커진다.
  • PROPOSAL Adam은 step 크기가 정규화돼 있어 변화량과 trial 수의 상관이 일부 기계적일 수 있고, 위 목적함수의 retention 항 크기를 정할 문헌 측정도 거의 없다.
  • OPEN 명시적 바깥 루프로 갈지 순차 문제 안에서의 창발에 맡길지는 정해지지 않았다.

현재 생각과 지속 기억의 읽기

06 §5 · 식 E8–E11

E8 · schema read와 depth read

PROPOSAL 06 §5 줄 73 · 제안 표기

하는 일. 현재 hidden에서 지속 기억의 schema를 읽고, 이번 생각의 depth bank에서 이전 표현을 읽는다.

입력 → 출력. 입력은 ht,r, Mt,r, Dt,r이고, 출력은 schema read 결과 mt,r과 depth read 결과 dt,r이다. 문서는 이 한 줄에 두 식을 함께 적었다.

mt,r=SchemaRead(ht,r,Mt,r),dt,r=DepthRead(ht,r,Dt,r)

기호. SchemaRead와 DepthRead는 읽기 연산이며 문서는 형태를 정하지 않았다. Mt,r은 시각 t·recursion r에서의 memory다.

E9 · 판단기의 출력 네 가지

PROPOSAL 06 §5 줄 75 · 제안 표기

하는 일. 읽은 것들을 controller 정책 πψ에 넣어 이번 loop의 계산 mask·쓰기 대상·강도·통신·종료 정책을 한꺼번에 낸다.

입력 → 출력. 입력은 ht,r, mt,r, dt,r, ct,r이고 출력은 네 값 (at,r,ut,r,ηt,r,bt,r)이다.

(at,r,ut,r,ηt,r,bt,r)=πψ(ht,r,mt,r,dt,r,ct,r).

기호. a는 token·block 계산 mask, u는 write 대상·허용, η는 강도, b는 통신·종료 등 정책을 나타내는 제안 표기다(문서).

E10 · hidden state의 한 loop

PROPOSAL 06 §5 줄 79 · 제안 표기

하는 일. hidden state를 mask a가 허용한 부분만 계산 블록 Fθ로 한 번 갱신한다(recursion 한 단계).

입력 → 출력. 입력은 ht,r, xt, mt,r, dt,r, mask at,r이고 출력은 ht,r+1이다.

ht,r+1=ht,r+at,r⊙Fθ(ht,r,xt,mt,r,dt,r)

기호. ⊙은 원소별 곱이다(문서가 정의하지 않아 표준 표기로 읽었다). Fθ는 느린 파라미터 θ를 쓰는 계산 블록이다.

E11 · 지속 기억의 선택적 갱신

PROPOSAL 06 §5 줄 81 · 제안 표기

하는 일. 지속 기억 M을 쓰기 허용 u가 허락한 부분만, 강도 η의 갱신 연산으로 고친다.

입력 → 출력. 입력은 Mt,r, 허용 ut,r, 강도 ηt,r, 증거 ℰt,r이고 출력은 Mt,r+1이다.

Mt,r+1=Mt,r+ut,r⊙𝒰ηt,r(Mt,r,ℰt,r).

기호. 𝒰η는 강도 η로 쓰는 갱신 연산, ℰ는 출처와 대상 경험에 결속된 증거다(문서).

PROPOSAL 내부 update를 임시 상태에서 수행한 뒤 commit할지, 온라인 committed state를 버전별로 갱신할지는 상태 계약에서 선택한다(06 §5). 위 네 식은 "제안 표기"이며 어떤 구현의 정확한 식도 아니다.

비용 민감한 제어

06 §6 · 식 E12

E12 · 비용 민감한 제어 목적

PROPOSAL 06 §6 줄 89

하는 일. 한 요청이 아니라 연속 경험 구간 전체에서 과제 손실·계산 비용·망각·위험을 한 목적으로 묶는다.

입력 → 출력. 입력은 시각 t마다의 네 항과 가중치이고 출력은 기대 목적 J이다.

J=𝔼[∑t(ℒtask,t+λcCt+λfℒforget,t+λrℒrisk,t)].

기호. ℒtask,t는 과제 손실, Ct는 시각 t의 비용, ℒforget,t는 망각 손실, ℒrisk,t는 위험 손실이고, λc,λf,λr는 가중치다. 이 λf는 §3의 피드백 손실 가중치와 같은 글자의 다른 쓰임이다.

PROPOSAL C에는 encoder, core 반복, routing, depth read, write·backward, retrieval·offload, decoder가 포함된다. Sleep는 online latency와 별도로 표시하되 amortized total compute(여러 요청에 나눠 센 총 계산)에는 포함한다. 지금 학습해서 다음 요청에서 비용을 줄이는 선택을 평가하려면 horizon(앞을 내다보는 구간)이 필요하다. 추가 loop의 예상 효용과 비용을 비교하는 halting(언제 멈출지 정하는 규칙)이 후보이고, familiarity만으로 halt하지 않는다. 동일 질의에 여러 (loop, update) 조합을 평가해 요구 품질을 만족하는 저비용 행동을 학습 신호로 쓸 수 있지만 이 teacher 비용도 기록한다(06 §6).

  • LITERATURE (fulltext-read) 같은 품질의 추론 계산량을 잰 논문은 읽은 11편에서 찾지 못했다. HWU20의 절감도 학습 epoch이다. 개념 수준의 근거는 SPECTRUM26(accommodation이 더 많은 시간과 계산을 요구한다는 정성적 서술)과 SWAMI23(posterior 엔트로피 감소, 1회 EM으로 충분)뿐이다.
  • PROPOSAL H-COMPUTE는 문헌 지지가 가장 약한, 사실상 우리 고유 가설이다. halting의 후보 신호는 CSCG(확률적 hidden-state graph 모형) posterior 엔트로피(SWAMI23), 기억 recall 신뢰도(KUMAR26의 0.6 임계값), attractor 수렴 탐침(CHU25 S-C.3의 응용)이며 이 신호들의 계산 절감 효과는 시험되지 않았다. 고정 깊이의 품질–계산 곡선을 먼저 얻고, Cϵ*의 첫 추정은 문헌 대조 없는 우리 실측으로 적는다.
  • USER (B03, 2026-10-05) SGD·cross entropy·오차 기반 학습은 대량 data에 유리하다. 우리는 적은 data가 시간축으로 계속 들어오고 빠르고 성급한 일반화를 누적하는 pattern·surprise 기반 학습이 필요하다. PROPOSAL 시행착오로 신호를 얻는 학습(RL(강화학습), bandit, 여러 행동 조합의 teacher 탐색)은 시도 횟수가 곧 비용이다. 경험 직후의 빠른 경로는 이런 신호를 요구하지 않고 한 관측에서 얻는 신호(예측 잔차·정정·피드백)로 먼저 갱신한다. 시행착오형 신호는 controller 학습과 Sleep 단계에서만 쓰며 시도 횟수와 teacher 비용을 총 계산에 포함한다.
  • ARCHIVE Melete v0.2는 경험 직후의 첫 방법을 case lookup·no-write·normalized delta·작은 SGD write로 두고, 여러 경험 뒤의 층에서만 필요한 경우 meta-learning·RL을 쓰도록 층을 나눴다. OPEN 시행착오형 학습을 후속 단계의 어느 지점에서 허용할지는 정하지 않았다.

제한된 선형 표본 효율 설명

06 §7 · 식 E13–E14 · 문서 표현 그대로의 상한: "제한된 선형 표본 효율 설명"

E13 · 선형 schema 모형

PROPOSAL 06 §7 줄 109 · 상한: "제한된 선형 표본 효율 설명"

하는 일. "schema가 d차원 입력 가운데 r차원 부분공간만 쓴다"는 가장 단순한 선형 모형을 정의한다.

입력 → 출력. 입력은 부분공간 Uk, 새 과제의 계수 a, 잡음 ϵ이고 출력은 관측 y이다.

y=x⊤Uka+ϵ,Uk⊤Uk=Ir,x~𝒩(0,Id),ϵ~𝒩(0,σ2),r≪d.

기호. Uk⊤Uk=Ir은 Uk의 열이 서로 직교하고 길이가 1이라는 뜻이다(d×r 크기로 읽는다). x~𝒩(0,Id)는 입력이 d차원 표준 정규분포, ϵ~𝒩(0,σ2)는 분산 σ2의 잡음, r≪d는 부분공간 차원이 입력 차원보다 훨씬 작다는 뜻이다.

E14 · 기대 초과 예측 오차

PROPOSAL 06 §7 줄 113 · 상한: "제한된 선형 표본 효율 설명"

하는 일. 올바른 Uk를 알고 새 과제의 n개 독립 관측으로 계수 a를 OLS(ordinary least squares, 최소제곱)로 추정할 때, 새 noiseless signal에 대한 기대 초과 예측 오차를 준다.

입력 → 출력. 입력은 σ2, r, n(단 n>r+1)이고, 출력은 기대 초과 MSE(mean squared error, 평균 제곱 오차)다.

𝔼[MSEsignal]=σ2rn−r−1.

기호. MSEsignal은 noiseless signal에 대한 초과 예측 오차다. Uk를 쓰지 않는 d차원 OLS에는 n>d+1일 때 r 대신 d가 들어간다. schema는 새 task에서 추정할 자유도를 줄일 수 있다는 제한된 설명이다.

"제한된 선형 표본 효율 설명"의 한계(문서가 직접 적은 것). Uk의 발견·선택 비용, misspecification(모형이 틀린 경우), nonlinear language, noise modeling, intercept(절편) 등은 이 식에 포함되지 않는다(06 §7). 이 식은 "구조를 알면 추정할 것이 줄어든다"는 직관의 한 이상화일 뿐, 언어 모델에서 그렇게 된다는 증거가 아니다.

Loop 감소의 제한된 수렴 설명

06 §8 · 식 E15 · 문서 표현 그대로의 상한: "Loop 감소의 제한된 수렴 설명"

E15 · loop당 수축 가정

PROPOSAL 06 §8 줄 121 · 상한: "Loop 감소의 제한된 수렴 설명"

하는 일. memory가 고정이고 F가 올바른 해 h* 근방의 수축(contraction)이라고 가정하면, loop를 한 번 돌 때마다 해까지의 거리가 κ배 이하로 줄어든다고 쓴다.

입력 → 출력. 입력은 현재 hidden hr, 올바른 해 h*, 수축 계수 κ이고, 출력은 다음 loop의 거리 상한이다.

‖hr+1−h*‖≤κ‖hr−h*‖,0<κ<1

기호. h*는 올바른 해, κ는 0<κ<1인 수축 계수, ‖·‖는 거리(노름)다. 따라서 문서는 ‖hr−h*‖≤κr‖h0−h*‖을 이끌어 낸다(문장 안 식). 좋은 schema는 초기 오차나 반복 변환을 개선할 수 있다.

"Loop 감소의 제한된 수렴 설명"의 한계(문서가 직접 적은 것). 실제 Transformer가 contraction이라는 주장도, 고정점이 정답이라는 주장도 아니다. 반복 중 weights가 바뀌면 이 단순 정리를 그대로 적용할 수 없다(06 §8). 같은 맥락에서 06 §10은 "loop 증가가 단조적으로 정답률을 올린다"를 아직 정리가 아닌 주장으로 분류한다.

프로젝트의 핵심 측정량

06 §9 · 식 E16–E17 · 편향 이득·해악 지표는 08 §6

E16 · 최소 계산 예산 Cϵ*

PROPOSAL 06 §9 줄 127 · 핵심 측정량

하는 일. 새로운 entity·value·binding이지만 관계 구조를 공유하는 과제에서 오차를 ϵ 이하로 만드는 데 필요한 최소 계산 예산을 정의한다.

입력 → 출력. 입력은 모델 M, 새 과제 집합 𝒯new, 예산 C, 목표 오차 ϵ이고, 출력은 최솟값 Cϵ*(M)이다.

Cϵ*(M)=min{C:Error(M;𝒯new,C)≤ϵ}.

기호. Error(M;𝒯new,C)는 예산 C에서 모델 M이 새 과제에서 내는 오차다. 최소값은 실제로 측정한 budget grid 안에서만 계산하고, 측정하지 않은 threshold crossing을 보간해 단정하지 않는다. query-level noise와 history·world-level variation을 나눠 통계 처리한다(06 §9).

E17 · 경험 전후 Cϵ* 비교

PROPOSAL 06 §9 줄 131 · 검증 조건

하는 일. 경험(또는 Sleep) 전후 모델의 Cϵ*을 비교해, 같은 구조를 공유하는 새 사례에서 필요한 계산이 줄었는지 확인한다.

입력 → 출력. 입력은 Mbefore, Mafter와 같은 𝒯new·ϵ이고, 출력은 부등식이 성립하는지(예·아니오)다.

Cϵ*(Mafter)<Cϵ*(Mbefore)

기호. Mbefore와 Mafter는 경험 전과 후의 모델이다. 이 식은 확인할 조건이지 이미 성립한 사실이 아니다.

검증 체계에서 쓰이는 방식

PROPOSAL 검증 체계의 대표 실험은 모델의 세 상태를 비교한다. S0는 retrofit과 기본 학습을 마친 상태, SE는 지정된 경험을 축적한 상태, SES는 같은 경험으로 Sleep까지 수행한 상태다. 먼저 controller를 우회하고 고정 depth 격자 r에서 품질 Qs(r)을 재며, 다음 단계에서 controller를 켜 실제 policy가 저비용 경로를 선택하는지 본다. PoC PASS 조건의 첫째는 "SES가 S0보다 Cϵ*가 낮다(비용식 전체, 측정한 budget grid 안에서만 비교)"이고, 이것이 gate G-COMPUTE(Cϵ*(SES)<Cϵ*(S0)이며 비용은 전체를 포함하고 쉬운 문제 편중이 아닐 것)다(08 §3, 08 §6). G-COMPUTE는 E17의 비교를 경험 전의 S0와 Sleep까지 거친 SES에 적용한 것으로 읽힌다(이 백서의 정리). 같은 품질의 추론 계산량을 잰 문헌이 없어 이 비교에는 문헌 기준값이 없다. 결과를 보기 전에 사전 등록하며, 값은 pilot 뒤에 정한다(승인된 수치가 아니다).

핵심 측정량 (06 §2·§9, 08 §3·§6) — PROPOSAL

아직 정리가 아닌 주장

06 §10 · 문서 표현 그대로의 상한: "아직 정리가 아닌 주장"

OPEN 다음 다섯 명제는 정리가 아니다. 반례와 비교 방법을 가진 OPEN 가설로 관리한다(06 §10).

  1. 모든 schema가 저랭크라는 명제.
  2. semantic abstraction level과 CMS(continuum memory system, 갱신 시간척도가 다른 여러 level의 기억) frequency가 일치한다는 명제.
  3. post-training이 반드시 schema를 분화한다는 명제.
  4. oscillator가 event scheduler보다 항상 효율적이라는 명제.
  5. loop 증가가 단조적으로 정답률을 올린다는 명제.

OPEN 문헌 검토 뒤 같은 방식으로 관리할 명제가 셋 더 들어왔다(sbl-fulltext-review §4 4.1·4.3). (1) 학습된 schema 구조가 같은 예산의 고정·무구조 대조보다 낫다는 명제 — 읽은 11편에 직접 비교가 없다. (2) 오류가 크면 새 구조를 만들고 작으면 미세 조정하는 규칙이 옳다는 명제 — STRUCTK25·SPECTRUM26의 정성 규칙이며 데이터가 없다. (3) 예외만 따로 저장하면 schema가 보존된다는 명제 — SPENS24 확장 모델의 설계이며 schema 개정과 다중 seed가 없다.

LITERATURE (fulltext-read) SPENS24: 확장 모델은 consolidation 전에도 prototype 쪽 왜곡을, DRM(Deese–Roediger–McDermott) 모형은 목록에 없지만 연관된 단어(lure)의 회상을 정성적으로 재현한다. PROPOSAL 위 명제들의 반례·실패 모드 후보는 잘못된 구조가 조용히 내용을 묶는 것(TEM20형 분리에서의 위험)과 schema 과적용(prototype 왜곡·DRM lure)이다(06 §10).
